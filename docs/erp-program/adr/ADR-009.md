# ADR-009: Security architecture and identity

| Field | Value |
|---|---|
| Status | PROPOSED |
| Approvers | Security architect; chief architect; technical lead; owner (data residency decision) |
| Review by | 2027-04-19 |
| Part | 02 (REQ-ARCH-F02 to F13) |

## Context
Authentication does not exist (Part 01 R-03). Constitution §10.1 requires Argon2id or an equivalent, MFA for privileged roles, secure cookies, CSP, server-side authorisation (N10), secrets in a vault and encryption of sensitive columns. DPDP Act 2023 applies to personal data; data residency defaults to India regions (REQ-ARCH-F11).

## Decision drivers
- Server-side authorisation everywhere (N10, N11)
- MFA for privileged, finance and approval roles
- India data residency by default; DPDP privacy by design

## Options considered
| Option | Assessment |
|---|---|
| Self-hosted or managed OpenID Connect identity provider with TOTP and WebAuthn (proposed) | Standard, audited protocols; SSO with SAML or OIDC for corporate users; sessions issued by the provider and verified by the application. |
| Application-built authentication | Full control, but the security burden is ours; §10.1 requires Argon2id, lockout, reset and revocation to be built correctly. |
| Third-party SaaS identity | Subject to a residency check; rejected until an India region is confirmed. |

## Decision
Use an OpenID Connect identity provider with MFA (TOTP and WebAuthn). The application holds server-side sessions in Redis with idle and absolute expiry and revocation; cookies are HttpOnly, Secure and SameSite. Authorisation is an RBAC + ABAC + SoD policy checked on every path (SE-8). Secrets live in a vault; sensitive columns are encrypted with keys in a KMS. Data residency is India by default; the provider's region is a condition of approval.

## Consequences
- Step-up MFA for payment release, bank-detail change, permission grant, large export and high-band approvals (SE-8).
- A breach-notification runbook is required before go-live (DPDP).

## Fitness function
Authorisation matrix tests (generated per permission key: allowed 200, disallowed 403, out-of-scope filtered) once Part 07 exists. Secret scan in CI (Part 01 inventory pattern) and a dependency audit (R-02) before deployment.

## Rollback
Identity provider can be swapped behind the session interface; sessions are revoked on rollback.
