# ADR-008: Mobile and offline architecture

| Field | Value |
|---|---|
| Status | ACCEPTED (2026-10-19, approved by the owner, D-038) |
| Approvers | Chief architect; technical lead; Project Director delegate (field decisions) |
| Review by | 2027-04-19 |
| Part | 02 (REQ-ARCH-F02 to F13) |

## Context
Field use needs 72 hours of offline capture, an encrypted local store, a command queue and conflict rules (AC-7 offline, SE-7). The existing code is a web application; no native code exists.

## Decision drivers
- Offline capture for 72 hours (§10.3)
- Encryption of data at rest on the device (§10.1)
- One codebase where possible

## Options considered
| Option | Assessment |
|---|---|
| Progressive web app on the same Next.js application (proposed first) | One codebase; installable; service worker and IndexedDB. Limits on camera, GPS and background sync vary by platform. |
| React Native | Better native access; a second codebase and a second release process. |
| Existing native apps (none) | Not applicable. |

## Decision
Start as a PWA with a service worker, an encrypted IndexedDB store and a command queue. Conflicts follow SE-7: the server is authoritative; offline records are PROVISIONAL until accepted; approvals, payments, postings and master changes are online only. React Native is reconsidered only if a required device capability cannot be met in the PWA, and that finding must be evidenced.

## Consequences
- Encryption keys are derived from the user session and never stored in plain text.
- Sunlight mode uses the high-contrast theme (Annex A).

## Fitness function
Offline scenario tests (§10.2) for each field feature; a device capability matrix recorded for each target platform.

## Rollback
The PWA is additive; disabling the service worker returns the online application.
