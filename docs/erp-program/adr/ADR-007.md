# ADR-007: Front-end architecture

| Field | Value |
|---|---|
| Status | ACCEPTED (2026-10-19, approved by the owner, D-038) |
| Approvers | Chief architect; technical lead; design owner (DS-1) |
| Review by | 2027-04-19 |
| Part | 02 (REQ-ARCH-F02 to F13) |

## Context
Part 02 REQ-ARCH-F09 requires one design system, avoidance of micro-frontends unless justified, a single state manager, caching for server data, code splitting and accessibility. The repository already has a design system (Annex A) and a shell.

## Decision drivers
- One design system (N24)
- Fast first load on field devices (§10.3)
- Non-financial optimistic UI only (N9)

## Options considered
| Option | Assessment |
|---|---|
| Single Next.js application, in-repo design system (proposed) | Matches the existing shell; one deployable; code splitting per route. |
| Micro-frontends | Justified only when independent release of modules is a proven need; adds runtime coupling and a second styling contract. |
| Separate SPA with its own build | Duplicates routing and the design system. |

## Decision
Single Next.js application. Server state uses one library, TanStack Query (MIT, currently 5.104.5), the only server-state cache. Local UI state uses React state. Optimistic updates are allowed only for non-financial actions; financial actions wait for the server. Routes are code-split. Next.js 16 is the current major; the upgrade is a separate, tested change (see TECH_RADAR.md and risk R-02) and is not made under this ADR.

## Consequences
- Adding TanStack Query needs it on the allow-list when the first screen uses it.
- A second state manager needs a new ADR (CP-ARCH-01).

## Fitness function
Bundle budget (first-load JavaScript) checked in CI once screens exist; current first load 103 kB for the shell.

## Rollback
Remove TanStack Query by replacing its hooks inside src/components; no route structure changes.
