# ADR-003: Data architecture

| Field | Value |
|---|---|
| Status | PROPOSED |
| Approvers | DBA; chief architect; technical lead |
| Review by | 2027-04-19 |
| Part | 02 (REQ-ARCH-F02 to F13) |

## Context
The constitution requires PostgreSQL 15 or later, partitioning for high-volume tables, a read replica for reports, an analytics warehouse fed by change data capture, object storage for documents, and an outbox for events (AC-2, AC-3, AC-5, §7.2). Volume targets are in §10.3.

## Decision drivers
- Preserve the operational database and extend it (§7.1)
- Reporting must not slow transactions (AC-16)
- Targets: 10 M stock transactions a year; 5 M attendance punches a month; 100 GB of documents a month

## Options considered
| Option | Assessment |
|---|---|
| PostgreSQL 15+ operational store; replica for reports; warehouse via CDC (proposed) | Matches the constitution; one relational engine for the ledger and the protocol engine; partitioning handles the volumes in §10.3. |
| Document database as the primary store | Weak fit for the constraints the ledger needs (AC-7, AC-8). |
| Separate store per module | Breaks shared masters (N5) and the one-transaction rule (AC-1). |

## Decision
PostgreSQL 15 or later is the operational store. Redis is the cache, the rate-limit store and the session store (ADR-009). S3-compatible object storage holds documents (AC-9). Search starts with PostgreSQL full-text search; OpenSearch is added only when measured search latency breaches §10.3. High-volume tables (audit, events, stock ledger, attendance punches, telematics, notifications) are partitioned by time from creation (§7.2).

## Consequences
- Full-text search is a deliberate first choice to keep one data engine until the volume proves otherwise.
- Warehouse and replica are delivered in Parts 75 and 84, not here.

## Fitness function
Load probe for §10.3 targets (Part 01 REQ-DISC-F11 pattern) once a database exists; search latency p95 < 500 ms as the trigger for OpenSearch.

## Rollback
Partitioning and the replica are additive and can be removed before data is written; object storage keys are stored only as document_id references (AC-9).
