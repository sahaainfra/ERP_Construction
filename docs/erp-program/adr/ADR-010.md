# ADR-010: Analytics and AI architecture

| Field | Value |
|---|---|
| Status | PROPOSED |
| Approvers | Chief architect; security architect; product owner; CFO delegate |
| Review by | 2027-04-19 |
| Part | 02 (REQ-ARCH-F02 to F13) |

## Context
Certified KPIs need one metric catalogue with lineage (AC-16, Part 75). AI must be advisory, permission-scoped and logged (AC-16, N14). Provider choice affects data residency.

## Decision drivers
- Certified KPIs with lineage (SE-9)
- AI never writes business data (N14)
- Cost control and evaluation before rollout

## Options considered
| Option | Assessment |
|---|---|
| First-party dashboards and report builder over a warehouse and a semantic layer (proposed) | Keeps permission filtering inside the application; no external BI copy of the data. |
| External BI tool as the primary surface | Permissions and masking must be duplicated; data leaves the controlled boundary. |
| Model hosting: cloud API versus private hosting | Decided in Part 79 with an ADR once residency and cost are known. |

## Decision
First-party analytics: a warehouse fed by change data capture, a metric catalogue, and a semantic layer, all in Parts 75 and 76. AI runs through one gateway (AC-16) with provider abstraction, permission-scoped read tools, prompt and response logging without secrets, evaluation and cost quotas. The model-hosting option is decided in Part 79.

## Consequences
- No external BI tool in v1.
- AI output is labelled AI INTERPRETATION (AC-13).

## Fitness function
Metric lineage test (every certified KPI resolves to source transactions) in Part 75; AI tool permission tests in Part 79.

## Rollback
Analytics layer is read-only; it can be turned off by flag without affecting transactions.
