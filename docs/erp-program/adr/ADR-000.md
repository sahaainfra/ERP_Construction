# ADR-000: Application stack adopted for the new project

| Field | Value |
|---|---|
| Status | ACCEPTED (interim, owner decision D-002) |
| Approvers | Product owner (decided); technical lead to confirm in ADR-001 review |
| Review by | 2027-04-19 |
| Part | 02 (REQ-ARCH-F02 to F13) |

## Context
The owner chose Next.js with TypeScript for the new repository (DECISIONS.md D-002). Part 02 requires that stack choices be recorded as ADRs (AC-3). Part 01 scored the resulting shell at 1.50 on the fitness rubric, with the security dimension at 0 because authentication is not yet built.

## Decision drivers
- Owner decision already made
- One framework, one language end to end
- Reuse existing tooling in the repository

## Options considered
| Option | Assessment |
|---|---|
| Next.js 15 + React 19 + TypeScript (chosen) | Single language, App Router, server rendering, large ecosystem. Next 15 is the line installed; Next 16 is the current major (16.4.2, released 2026-10-15). |
| Vite SPA + separate Node API | Simpler build; two deployables and a second contract to maintain. |
| Other frameworks | Not evaluated against the constitution's stack reference (AC-3) in this ADR; a re-decision would need its own ADR. |

## Decision
Adopt Next.js (App Router) with React and TypeScript as the application framework. Lucide is the icon family (Annex A DS-10). Vitest and tsx are the test and script runners. Every package is listed in docs/erp-program/DEPENDENCY_ALLOWLIST.json with this ADR as its source.

## Consequences
- Upgrading Next to 16.x is a separate decision (see ADR-007 and TECH_RADAR.md); it is not made here.
- Server rendering and route handlers become the default API surface unless ADR-005 decides a separate API service.

## Fitness function
npm run arch:check (docs/erp-program/DEPENDENCY_ALLOWLIST.json lists every package and its ADR).

## Rollback
Re-decide through a new ADR; the code is small and the change is contained to src/app and src/components.
