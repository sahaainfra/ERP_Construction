# ADR-011: Infrastructure, environments and release

| Field | Value |
|---|---|
| Status | ACCEPTED (2026-10-19, approved by the owner, D-038) |
| Approvers | DevOps lead; chief architect; technical lead; owner (cloud provider and region) |
| Review by | 2027-04-19 |
| Part | 02 (REQ-ARCH-F02 to F13) |

## Context
Environments are required: dev, test, staging with production-like volume, preview or sandbox with synthetic data, production and DR (REQ-ARCH-F13). The repository has no infrastructure code and no cloud account is named in the source material. The cloud provider and region are not known to the agent and must be provided by the owner.

## Decision drivers
- Reproducible environments from code (IaC)
- Staging that restores a production-sized copy (§10.3)
- Blue-green or canary releases with rollback

## Options considered
| Option | Assessment |
|---|---|
| Containers with infrastructure as code (Terraform) and a managed PostgreSQL (proposed) | Portable; managed backups and PITR; fits India region requirements if the provider offers one. |
| Kubernetes from the start | Operational cost before the team and scale justify it; reconsidered at scale. |
| Single virtual machine with Docker Compose | Quick for a pilot; no HA, no tested restore path; acceptable for dev only. |

## Decision
Containerise the application and the workers. Provision environments with Terraform. Use a managed PostgreSQL with point-in-time recovery and a cross-region replica for DR (RPO 15 minutes, RTO 4 hours per §10.3). Deploy with blue-green or canary releases. Feature flags default OFF in production (U18). Kubernetes is deferred until scale evidence.

## Consequences
- Environment blueprint is in ENVIRONMENTS.md; the IaC is not yet written because the provider and region are not chosen (CF-012).
- Backups and restore tests are a release gate (Part 84).

## Fitness function
Staging restore test of a production-sized copy (Part 84); release rollback rehearsal recorded per release.

## Rollback
Infrastructure is code; a change is reverted by applying the previous state, after the database step is checked for reversibility (Part 03).
