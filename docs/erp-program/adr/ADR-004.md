# ADR-004: Database fitness: money and quantity types (REPLACE-candidate)

| Field | Value |
|---|---|
| Status | PROPOSED |
| Approvers | Technical lead; CFO delegate (financial data); DBA; Part 22 owner once assigned |
| Review by | 2027-04-19 |
| Part | 02 (REQ-ARCH-F02 to F13) |

## Context
Part 01 scored the domain formula library at 2.23 with data integrity 0. Golden case commercial.priceVariation returns 999.9999999999995 for an expected 1000, because JavaScript numbers are binary floating point. AC-7 forbids floating point for money. This is criterion 5 of §7.3 (the data model makes integrity impossible), so the component is a REPLACE-candidate. Nothing is persisted yet, so the change is cheap now.

## Decision drivers
- Exact money, quantity and rate arithmetic (AC-7)
- Decimal types on the database side: DECIMAL(18,2) amounts, DECIMAL(18,4) rates, DECIMAL(18,3) quantities, DECIMAL(9,4) percentages, DECIMAL(18,8) exchange rates
- One library for decimal arithmetic in the application

## Options considered
| Option | Assessment |
|---|---|
| decimal.js 10.6.0 (MIT) in the application; NUMERIC in the database (proposed) | Exact decimal arithmetic in TypeScript; NUMERIC matches AC-7. One new dependency, listed in the allow-list when approved. |
| Integer minor units (paise) everywhere | Exact for money; awkward for rates and percentages with 4 to 8 decimals. |
| Keep floats and round at display | Rejected: rounding then differs between screens and the ledger. |

## Decision
Replace JavaScript number arithmetic for money and quantity in src/domain/ with decimal arithmetic before any persistence. Rounding happens only at policy points (AC-7, Part 22). The float-based functions are retired by a golden-test change that shows the new values and is reviewed under N4 (the baseline check fails until the change is intended and re-captured).

## Consequences
- Golden values change for money formulas; this is a reviewed change under N4, not a silent one.
- The decimal library joins the allow-list (ADR-004 is its source).

## Fitness function
Golden case commercial.priceVariation must equal 1000 after the change; a test asserts that no money function returns a value with more than the policy's decimal places. Both are added when the change is made.

## Rollback
Before persistence: revert to the float functions (the baseline still records them). After persistence: expand-migrate-parallel-run under Part 00 §7.4, with difference reports.
