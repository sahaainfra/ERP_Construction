# ADR-001: Architectural style: modular monolith with bounded contexts

| Field | Value |
|---|---|
| Status | ACCEPTED (2026-10-19, approved by the owner, D-038) |
| Approvers | Chief architect; technical lead; product owner |
| Review by | 2027-04-19 |
| Part | 02 (REQ-ARCH-F02 to F13) |

## Context
The programme has 86 Parts, one database and many shared engines (constitution AC-1). The team and infrastructure are not yet sized. Microservices add network failure modes, distributed transactions and operational cost before the domain is known.

## Decision drivers
- Shared engines need one transaction and one audit log (AC-1, AC-12)
- Team size and skills are unknown (Part 02 §4)
- Scale hot-spots must still be extractable (REQ-ARCH-F02)

## Options considered
| Option | Assessment |
|---|---|
| Modular monolith (proposed) | One deployable; modules as packages with published interfaces; extract later on evidence. |
| Microservices from the start | Independent scaling and release; distributed transactions for every posting, approval and stock move. |
| Serverless functions | Cheap at low load; cold starts and state handling make the ledger and the protocol engine harder to keep consistent. |

## Decision
Build a modular monolith. Each module code (Annex C) is a bounded context in its own folder with api/, domain/, infra/ and events/. Modules call each other only through api/. Hot-spots (attendance ingestion, telematics, notifications, document rendering, analytics) are extracted only when an ADR shows a scaling, isolation or release-cadence need.

## Consequences
- One deployment unit to start with.
- Boundaries must be enforced by tooling, not by convention.

## Fitness function
scripts/erp-program/architecture-check.ts (npm run arch:check) fails on any cross-module import outside the rules in src/program/architecture.ts. Today: 0 violations across 21 local imports. The module-folder rule is added when the first module is built.

## Rollback
Modules remain in one repository; extraction is reversed by moving the module back in-process behind the same api/ interface.
