## 4. Enhancements

- **Security.** Keyed masking (B3). Credentials are written atomically with their user (B2). Dependency advisories closed where the fix stays on the approved line (B4). Connector destinations are checked against private addresses and redirects are refused (Part 11 S1).
- **Reliability.** The migration rollback path is now tested on every run of the database tests (B1). The relay measures lag only after a successful publish (B7).
- **Accessibility and UI.** Shared templates and state components cover loading, empty, error, permission, offline, conflict and failure states (Part 12 S3). Each state names what happened, why, and what to do. Browser checks at phone, tablet and desktop widths pass with no axe violations.
- **Architecture.** No restructuring. Changes are additive, and existing modules keep their interfaces.
- **Not done (needs a decision or an ADR):** performance tuning, a load test, and a metrics endpoint. The volume and load tooling is part of Part 09 S3, which is not built.

## 6. Database and migration report

- **Schema changes in this review:** none. The one change is the down script of the foundation migration (B1); the up scripts and schemas are unchanged.
- **Rollback rehearsal (new test):** all 18 migrations apply, all 18 roll back to an empty schema, and all 18 apply again with nothing pending. It runs on the test database only.
- **Data protection:** no production data was touched. The test database is reset by the test suite, as before. Production backups use `npm run db:backup`; the restore check is `npm run db:restore-check`.
- **Rollback instructions:** `npm run db:down -- 1` reverts the most recent migration; `npm run db:down -- N` reverts the last N. Run `npm run db:backup` first. A full rollback is only for an empty or disposable database.

## 9. Execution instructions

Run from the repository root. Node 22 is required (`.nvmrc`).

```bash
npm ci                                  # install exact dependencies from the lock file
cp .env.example .env.local              # application environment; fill in the keys below
cp .env.test.example .env.test          # test environment
# Generate each key once and put it in both files (never commit them):
openssl rand -base64 32                 # TOKEN_SIGNING_KEY
openssl rand -base64 32                 # MFA_ENCRYPTION_KEY
openssl rand -base64 32                 # INTG_VAULT_KEY
openssl rand -base64 32                 # MASKING_KEY
```

Database (PostgreSQL 16; see `LOCALHOST.md` and `scripts/db/setup-local.sql` for roles and databases):

```bash
npm run db:status                       # which migrations are applied
npm run db:migrate                      # apply pending migrations
```

Checks and tests:

```bash
npm run check:all                       # the 9 quality gates (needs the database running)
npx vitest run                          # unit and integration tests
npx playwright test                     # browser checks (set PLAYWRIGHT_CHROMIUM_PATH if the bundled browser is not installed)
npm run build                           # production build
```

Run the application:

```bash
npm run dev -- -p 3000                  # development server
npm run build && npm run start -- -p 3000   # production server
```

## 10. Localhost access

The application is configured for port 3000 (`playwright.config.ts`, `npm run dev`). Port 3000 was free at the time of the review. The server runs in the review container and is reachable there at `http://localhost:3000/`. It is not reachable from another machine. To use it, run the commands in section 9 on your own machine.
