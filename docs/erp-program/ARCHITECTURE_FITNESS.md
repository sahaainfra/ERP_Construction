# ARCHITECTURE_FITNESS

Part 01, REQ-DISC-F10. Scored with the rubric in Part 01 §7. Scores are 0–5 per dimension; N/A means the dimension does not apply and its weight is removed from the total. The table is generated by `scripts/erp-program/fitness-report.ts` from `src/program/fitness.ts`, where the evidence and the scores live.

## Executive summary (for the owner)
1. **Four components exist and are scored.** Their weighted scores run from 1.50 to 4.08.
2. **The application shell has no security controls.** It scores 0 on security, which triggers the §7 rule: a Critical finding goes to Part 08. The cause is absence, not an insecure design.
3. **The domain formula library uses floating-point money.** The golden case `commercial.priceVariation` returns 999.9999999999995 for an expected 1000. AC-7 forbids this. The recommendation is REPLACE-candidate under §7.3 criterion 5 (its data model makes integrity guarantees impossible). The practical fix is a decimal type before any persistence. It is cheap now because nothing is persisted.
4. **The programme index and the token pipeline are the strongest parts.** Both fail loudly on bad input and are covered by tests.
5. **Fourteen systems are absent and are not scored.** Scoring an absent system as 0 would misstate the evidence, so they are listed separately.
